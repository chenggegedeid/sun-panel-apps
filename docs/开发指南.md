# 开发指南

三个微应用共用同一套脚手架，只是 `src/` 与 `config/` 不同。改代码前先读这一页，能省掉大半试错。

## 环境

- Node.js 18 以上（Vite 5 的要求）
- npm（三个目录各有独立的 `package-lock.json`，不要共用依赖）

## 目录约定

```
calendar/ music/ gately/     三个独立工程，互不依赖
├─ config/
│  ├─ app.config.js          应用信息：microAppId、版本、权限、数据节点
│  └─ components.config.js   组件注册：卡片尺寸、窗口名称与尺寸
├─ src/
│  ├─ components/            卡片 / 页面 / 设置页
│  ├─ utils/                 接口、状态、格式化
│  └─ main.js                入口，注册 Web Components
├─ locales/                  zh-CN.js / en-US.js（源文件，构建时编译成 json）
├─ build/                    构建脚本（生成 app.json、编译语言包、打包、出图标）
├─ scripts/                  模板同步工具
└─ packages/                 打包产物（不进仓库）
```

## 常用命令

| 命令 | 作用 |
|---|---|
| `npm run dev` | 开发服务器 + 热更新 |
| `npm run pack` | 生产打包，产物落在 `packages/` |
| `npm run gen` | 只重新生成 `app.json` 与语言包 |
| `npm run icon` | 重新生成图标（`public/icon.png`） |
| `npm run lint` / `npm run lint:fix` | ESLint 检查与自动修复 |
| `npm run preview` | 本地预览页 |
| `npm run update` | 从官方模板同步公共文件 |
| `npm run clean` | 清理 `dist/`、`packages/` |

## 构建链路

`app.json` 和语言包都是**生成物**，不要手改：

```
config/app.config.js ──┐
config/components.config.js ──┴─→ build/generators/app-json.js ─→ app.json
locales/*.js ──────────────────→ build/generators/locales-generator.js ─→ locales/*.json
```

改版本号、权限、卡片尺寸，全部改 `config/`，然后 `npm run gen` 或直接 `npm run pack`。

## 本地预览

每个工程根目录都有预览页，用查询串切换场景：

| 工程 | 预览页 | 常用参数 |
|---|---|---|
| calendar | `preview.html` / `preview-store.html` / `preview-pages.html` | 见文件头注释 |
| music | `preview-store.html` | 同上 |
| gately | `dev-preview.html` | `?shot=1` 纯净截图、`?panel=main`、`?tab=certs`、`?w=390` 手机宽度 |

`gately` 另外带一个本地模拟器 `tools/mock-gately.js`，`npm run dev` 时会挂在 `/mock-gately/*`，提供和真实接口同结构的假数据。改接口层时先对着模拟器验，再上真机。

## 模板同步

三个工程都带 `scripts/update-template.mjs`，用于把官方模板（[microapp-hello-world](https://github.com/Sun-Panel/microapp-hello-world)）的公共文件同步过来：

```bash
npm run update -- --dry-run    # 先看会改哪些文件
npm run update                 # 同步
npm run update -- --force      # 本地改过的也覆盖（慎用）
```

要同步哪些文件由 `scripts/template-files.json` 决定，可以按需增删。`vite.config.js`、`build/` 这类公共部分建议保持同步；`src/`、`config/` 属于各应用自己的，不要同步。

## 新增一个应用

1. 复制最接近的那个工程目录（只要 `config/`、`build/`、`scripts/`、`locales/`、`package.json`、`index.html`、`vite.config.js`）
2. 改 `config/app.config.js` 的 `microAppId`（必须以开发者标识开头，例如 `chenggegedeid-`）与应用名
3. 改 `locales/*.js` 的文案
4. 清掉 `src/` 换成新应用的组件
5. `npm install && npm run dev` 起得来，再写 `README.md` 与 `CHANGELOG.md`
6. 在根 `README.md` 的应用清单表里加一行

## 调试技巧

- 微应用跑在宿主的 Shadow DOM 里，浏览器 `--dump-dom` 读不到内容；用 Chrome DevTools 选中 `gately-page-*` / `gately-widget-*` 节点，再展开 `#shadow-root` 看
- 打包后文件名带版本号，排查「改了没生效」先确认装的是新包（`unzip -p packages/*.zip app.json` 看 version）
- 卡片尺寸靠 CSS 容器查询（`container-type: size`）适配，调试时直接改容器宽度比改视口更快
