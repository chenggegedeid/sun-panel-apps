# 发布与上架

从改版本号到商店过审，按这个顺序走，不容易漏。

## 1. 改版本号

只改一处：

```js
// config/app.config.js
export default {
  microAppId: 'chenggegedeid-Gately',
  version: '1.3.0',        // ← 改这里
  ...
}
```

`app.json` 是构建时生成的，不用手改，也不要手改（下次 `npm run pack` 会被覆盖）。

**版本号怎么跳**

| 情况 | 示例 |
|---|---|
| 修 bug、改文案 | 1.3.0 → 1.3.1 |
| 加功能、改交互 | 1.3.0 → 1.4.0 |
| 改数据结构、不兼容旧配置 | 1.3.0 → 2.0.0 |

改完顺手在 `CHANGELOG.md` 顶部加一条，格式对齐已有的条目（日期 + 分类小标题 + 要点）。**商店的「更新说明」可以直接复制这一段。**

## 2. 打包

```bash
npm run lint          # 先过检查
npm run pack
```

产物是 `packages/<microAppId>-<version>.zip`，内含：

```
app.json
icon.png
locales/zh-CN.json
locales/en-US.json
main.js
```

`dist/`、`packages/` 都在 `.gitignore` 里，不进仓库。

## 3. 打包后自检

三行命令，确认装上去的确实是你以为的那版：

```bash
unzip -l packages/*.zip                                  # 五个文件齐不齐
unzip -p packages/*.zip app.json | head -20              # 版本号、microAppId、权限
unzip -p packages/*.zip locales/zh-CN.json | head -5     # 文案有没有漏
```

再确认两件事：

- `main.js` 体积没有异常暴涨（正常在 130–180 kB，gzip 40 kB 上下）
- 图标 MD5 与源文件一致：`unzip -p packages/*.zip icon.png | md5sum` 对比 `public/icon.png`

## 4. 截图

商店首图决定点击率，别用随手截的。

| 要求 | 做法 |
|---|---|
| 尺寸 | 2 倍像素输出（`--force-device-scale-factor=2`），避免商店压缩后发虚 |
| 命名 | `01-xxx.png` 起，按展示顺序编号 |
| 数量 | 6–10 张；第一张放「全部卡片尺寸」，第二张放主界面 |
| 内容 | 至少一张深色、一张浅色；有手机版的补一张竖屏 |
| 纯净 | 不要出现浏览器边框、滚动条、滚动条阴影、书签栏 |

各工程的截图放在 `docs/screenshots/`，随仓库一起提交，README 里引用。

**不要**把调试用的临时截图（`t-xxx.png`、`v1.png`）留在目录里，提交前 `ls` 一眼。

## 5. 商店要填的信息

| 字段 | 注意 |
|---|---|
| 应用名 | 与 `locales` 里的 `APP_NAME` 一致 |
| 版本号 | 与 `app.json` 的 `version` 完全一致，否则审核会打回 |
| 简介 | 讲清「这个应用替你做什么」，不要只列技术栈 |
| 权限说明 | 声明了 `network` 就要写清楚「只连用户自己填的地址，不经过第三方」 |
| 截图 | 见上一节 |

三个应用当前的标识：

```
chenggegedeid-Calendar   日历倒计时   2.0.0
chenggegedeid-Music      音乐         3.0.3
chenggegedeid-Gately     Gately 网关  1.3.0
```

## 6. 审核最容易卡的地方

**网络权限与白名单**
`networkDomains: ['*']` 是因为目标地址由用户填写、域名不可预知。审核若问，答：只向用户自己填写的地址发请求，不经过任何第三方；所有请求走宿主 `network.request`，应用代码不直接调 `fetch`。

**静态扫描的 `innerHTML` / `fetch` 提示**
来源与判断写在 [SECURITY.md](SECURITY.md)，审核需要时直接给这份。

**「连不上」类反馈**
先让用户点设置页的「诊断」按钮，它会打出真实请求 URL、状态码、content-type 与响应开头。比让用户描述现象快得多。

## 7. 发版检查清单

- [ ] `config/app.config.js` 版本号已改
- [ ] `CHANGELOG.md` 加了对应条目
- [ ] `README.md` 里的版本号 / 产物名已同步（如果有写）
- [ ] `npm run lint` 无 error
- [ ] `npm run pack` 成功，产物自检通过
- [ ] 截图更新（改了界面就要重拍）
- [ ] 提交记录按 [提交规范](提交规范.md) 写
- [ ] 打 tag：`git tag -a <app>-v<version> -m "..."`，push 时带 `--follow-tags`
- [ ] 商店提交后，把包和截图复制一份到本地归档目录
